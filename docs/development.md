# 设计与验证记录

本文回顾文档导入之后的主要迭代，保留问题、设计取舍、验证及未解决限制。
日期来自开发记录，不代表每个阶段都有独立 Git 提交；已提交的历史见 [开发演进](../CHANGELOG.md)。

## 网页与会话

原命令行流程缺少上传、资料预览和连续阅读入口。网页将文件、对话、来源和输入分区展示，
以文件名及内容摘要识别切换，并将解析与向量缓存限制在当前会话范围。

后续加入有限历史：只发送成功问答，失败结果不作为模型历史；清空或切换文档会重置。
历史仅帮助理解指代，不能作为文档证据。运行检查覆盖普通重新运行不重复请求和保存，
实际开发题中加入需要前置问答的指代问题。刷新或重启的持久化仍不在范围内。

## 2026-10-11：全文概括

只检索少量片段无法等同于概括全文，因此新增 `summarize_document`，
使用全部可提取文字及真实来源，而不是复用 Top-K 检索上下文。

初版对超限全文直接拒绝，避免静默截断；记录输入块数、字符数和来源。
短文与工具选择检查通过后，再处理长文，不把简单短文反馈扩展为总体摘要质量结论。
离线检查区分空白、非正常结束、接口异常和请求预算不足。

## 2026-10-12：字段提取与引文

新增 `extract_document`，输入为字段列表，输出为结构化值、原文引文和来源。
缺失项必须明确为空，不从模型常识补写事实。

开发检查曾发现：在检查依据类型之前执行字符串包含判断，`None` 或数字会触发 `TypeError`。
调整为先校验值及依据的类型和非空条件，再验证引文是否存在于单块原文；八个受控场景复测通过。
连续引文匹配只能证明引用文字存在，不能证明字段值解释正确或缺失项确实不存在。

## 2026-10-13—14：长文批次、预算与进度

用有限批次替代初版整篇超限即拒绝：按含来源的字符数分组，不拆掉文档尾部；
每批上限 12000 字符、最多 10 批。摘要先逐批生成，多个批次再做最终汇总。

外层路由次数和工具内部请求分别计数，同时共享总预算；执行前检查完整计划，
中途失败不继续最终汇总、不保存部分成功为完整结果。

通过回调发布批次开始、完成和汇总事件。网页只呈现进度，任务层不依赖 Streamlit；
最终成功与否以返回状态判断，不能以进度条走满代替成功。
后续将向量资源准备延迟到检索，避免概括或提取先等待不需要的向量计算。

## 2026-10-15—18：客户端、流式与跨批次提取

统一客户端配置，避免网页和诊断脚本使用不同接口或模型名。
分别记录外层请求、概括、提取及检索相关耗时，不把流式显示当作总耗时已下降。

流式收集同时处理正文和工具参数增量，检查结束原因；
连接中断或异常结束时清除临时正文，不将半截答案作为完整结果。
网页保留工具前说明与最终正文的显示位置，多批摘要仅展示最终汇总正文。

跨批次提取由 Python 合并候选，不再请求模型“统一答案”。
开发中发现过逐批计时列表未实际传入单批函数、导致累计调用次数为零的问题；
修正接线后按真实请求尝试计数，并检查成功、失败及预算不足分支。
同值可以对应多处依据，不同值保留冲突；短文及合成两批样例仅提供有限范围的验证证据。

## 2026-10-19—20：结构化评测

三份虚构文档形成 12 道开发用例，覆盖事实、信息缺失、跨段限制、指代、冲突、概括和提取。
执行器读取并验证用例，批量运行，保存批次 ID、时间、配置及任务结果；
人工复核独立保存，`answered` 不自动等于内容通过。

已有 15 次运行包含 3 次历史接口失败，后续成功不抹去失败。
单次请求等待阈值调整至 120 秒，但没有证据据此认定超时根因已解决。
暂不继续无界扩充开发题，转向首版交付所需的环境与部署验证。

## 2026-10-21：交付准备

独立环境安装固定依赖并运行离线回归；增加网页模型下载开关检查，
将核心模块整理到 `rag_assistant/`，同步入口和根目录数据路径。
36 项自动化检查覆盖网页流程、下载开关、样例解析、批次完整性和异地工作目录启动。

Community Cloud 已完成页面启动和公开样例事实问答的首次验收；
概括、字段提取、跨会话隔离、性能和长期稳定性仍未全面验收。
OCR、多文档服务、持久化、权限及配额管理仍不属于当前已交付能力。

生成模型名称改为支持 `LLM_MODEL_NAME` 环境变量覆盖，默认值保持已有可运行配置，
便于在不改源码的情况下试用服务商提供的快速模型。
速度分析区分两段：首次检索的向量模型下载/初始化属于冷启动，
生成模型替换主要影响模型请求阶段，不能消除向量模型下载。
