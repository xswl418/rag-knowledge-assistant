# 架构与请求链路

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `web_app/app.py` | 上传、会话、缓存、流式显示、进度和结果渲染 |
| `rag_assistant/agent.py` | 工具选择循环、调用预算、异常状态和任务记录；提供命令行入口 |
| `rag_assistant/rag.py` | TXT/DOCX/PDF 读取、分组、切块、向量生成、检索和 JSONL 保存 |
| `rag_assistant/tools.py` | 三个工具的 schema、函数映射和参数校验 |
| `rag_assistant/document_task.py` | 全文批次计划、概括、字段提取、引文校验和候选结果合并 |
| `rag_assistant/streaming.py` | 收集流式文本与工具参数增量，保留结束状态 |
| `rag_assistant/conversation.py` | 从有限任务记录提取成功问答作为历史 |
| `rag_assistant/api_client.py` | 从环境变量创建共享配置的生成模型客户端 |

## 请求流程

```text
上传 TXT / DOCX / 文字型 PDF
  -> 提取正文、标题或页码 -> 切块
  -> 用户问题 + 当前文档有限历史 -> Agent 外层模型请求
     |-- 直接回答：仅适合问候、澄清等不需文档依据的任务
     |-- search_knowledge：按需准备向量 -> 检索 -> 回传资料 -> 继续回答
     |-- summarize_document：全文分批 -> 逐批概括 -> 必要时最终汇总
     `-- extract_document：字段校验 -> 逐批提取与引文校验 -> Python 合并
  -> 网页结果 / 命令行输出 -> 本地任务日志
```

外层每次响应只接受一条工具调用。无效 JSON 或参数回传为工具错误，允许模型在预算内修正。
检索最多执行三次，空结果允许改写查询；第三次仍为空则结束。
概括和提取直接返回完整结果或明确失败，不再追加外层模型改写。

概括按批生成，多个批次还需最终汇总；输入或预算超限时拒绝，不静默截断。
提取逐批校验字段顺序、缺失值和原文引文，再由 Python 合并；同值保留多处依据，不同值并列。
任何批次失败都不作为全文成功。

## 数据与资源

- 数据和日志路径以仓库根目录定位，不随模块移动而落到包目录；基础 RAG 读取 `data/samples/knowledge_base.txt`。
- 网页以名称和内容摘要区分上传文件；解析和文档向量采用会话范围缓存，向量模型为共享资源缓存。
- 检索资源延迟到实际调用检索工具时创建，普通重新运行不自动重发任务。
- 会话最多读取最近五条任务记录中的成功问答；历史回答不是文档证据。
- 命令行 Agent 不传跨问题历史；服务重启不会从 JSONL 自动恢复网页会话。
- `logs/agent_logs.jsonl`、`logs/query_logs.jsonl` 和评测日志均为运行时本地文件，不提交 Git。
- 生成模型默认值位于 `rag_assistant/rag.py`，可由 `LLM_MODEL_NAME` 环境变量覆盖；
  接口地址、密钥和模型名必须属于同一兼容服务配置。

## 诊断

任务记录包含 `status`、`error_message`、实际检索问题、检索步骤、调用次数及耗时。
分析故障时区分文档读取、检索准备、模型接口、概括或提取失败；请求超时并不直接证明上游故障原因。
`answered` 只表示运行得到有效文本，不能代替事实和来源的内容检查。
首次检索的模型下载和初始化属于网页冷启动成本，不能仅用更换生成模型消除。
