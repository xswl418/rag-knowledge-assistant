```text
向量与语义检索：文本向量是用一组数字表示文本特征的方式，可以用于比较问题和资料的相关程度。向量检索通常先把资料和问题转换为向量，再计算相似度并排序。语义检索关注含义相关性，即使问题和资料没有完全相同的关键词，也可能找到相关内容。得到相关资料以后，系统还需要把资料提供给生成模型，才能进一步组织成面向用户的回答。

检索阈值的取舍：在 OpenAI 的检索服务中，提高分数阈值会筛掉更多结果，但也可能排除有用资料。因此，筛选得更严格并不保证最终回答更好。该服务的评分规则和阈值不能直接作为其他检索系统的推荐配置。判断本地知识库的阈值是否合适，应结合实际问题，观察有用资料是否被保留、无关资料是否进入结果，而不是只看分数高低。

RAG 回答错误的定位：错误可能发生在检索阶段，也可能发生在生成阶段。检索阶段可能没有提供需要的资料，或带入太多无关内容；生成阶段则可能已经拿到了正确资料，却没有正确使用。排查时应先查看实际传给模型的参考内容，再对照最终回答。若资料缺失，重点检查检索；若资料充分但回答仍然错误，再检查模型使用资料的方式和提示词要求。

工具调用的分工：模型收到工具说明后，可以返回工具名称和参数，表达它希望执行的操作。应用程序根据请求调用实际函数，再把执行结果交回模型。模型随后可能给出答案，也可能继续请求其他工具。因此，模型提出搜索请求不等于搜索已经完成，工具返回内容也不一定就是最终答案。

工具说明与参数：工具定义应说明名称、用途和参数要求，帮助模型选择工具并组织输入。参数可以规定名称、类型和必填项。例如，一个检索工具可以要求传入字符串形式的问题。工具说明需要与实际函数的用途一致，模型生成的参数也需要由程序按约定处理。

HTTP 429 错误：在 OpenAI API 中，429 可能表示请求限速，也可能与余额或额度限制有关。处理时应查看具体错误信息，不能把所有 429 都当成请求太频繁。余额或额度不足时，反复重试不能解决问题，需要处理相应限制。

连接失败与超时：在 OpenAI Python SDK 中，APIConnectionError 表示连接问题，可检查网络、代理、证书或防火墙；APITimeoutError 表示请求超时。这两种异常不能简单归为同一种原因，排查应结合错误类型和实际网络情况。

回答质量评测：助手能正常返回文字，并不代表回答正确或满足用户需求。评测应先确定任务目标，再准备问题和判断标准。对于文档问答，可以分别检查所需资料是否被检索到、检索内容是否相关，以及最终答案是否解决用户问题。自动评分也需要结合人工检查，不能只凭回答流畅就认定系统可靠。

测试问题的来源：测试集可以结合真实用户问题、历史日志和人工设计的案例。除了常见问题，还应加入容易出现异常或暴露能力边界的情况。系统更新后应继续检查表现，并把新发现的问题补入测试集。这样可以观察修改是否有效，也能发现原本正常的场景是否受到了影响。

响应速度的优化：模型推理速度、输出长度和请求次数都会影响等待时间。减少不必要的连续请求、适当缩短输出，或并行处理彼此独立的任务，都可能降低延迟。流式输出可以让用户更早看到部分内容，但这不等于完整答案已经生成，也不必然缩短整个任务的完成时间。优化时应同时检查速度和回答质量。
```
