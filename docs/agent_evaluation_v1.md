# Agent：资料不足场景评测

整理日期：2026-09-27。

## 旧版问题与标准

问题：RAG 的检索相似度阈值应该设置为多少？

测试时的 `knowledge_base.txt` 第 1 段只解释 RAG 的检索生成流程，没有阈值设置方法或推荐值。其余三段也没有提供本题依据。以下 A01、A02 保留当时采用的严格知识库回答标准；最新产品规则见本文末尾。

合格回答应明确说明资料不足以确定阈值，不给出无依据的推荐数值、设置建议或伪造引用。不能把代码中的 `MINIMUM_SCORE=0.55` 当作通用推荐值。`answered` 仅表示获得非空白文本，不能代替人工内容判定。

## A02：固定提供第 1 段

- 入口：`manual_eval_insufficient_context.py`。
- 复用当前 Agent 的 `run_agent()`、系统提示词、工具参数校验和最多 3 次模型调用的限制。
- 用 `patch.dict` 临时将 `search_knowledge` 对应函数换成 `fixed_search`，退出该代码块时恢复原映射。
- 每次合法工具调用都只返回知识库第 1 段的知识块；资料来自当前文件，不生成补充资料。不加载向量模型、不执行向量检索。
- 结果中的 `score=None` 明确表示没有计算相似度，不能用于评价检索质量。
- 客户端是真实客户端，沿用当前环境中的接口地址和密钥。提示词和模型答案没有被模拟；配置中的模型名称不构成服务商实际后端模型的独立验证。
- 模型必须实际调用固定资料工具，并在后续返回非空白回答，才覆盖本次目标场景。直接回答、接口异常、空回复或达到调用上限应单独记录，不能算内容评测通过。
- 评测过程打印在终端，不写入日常任务的 `agent_logs.jsonl`。

运行方式：使用项目虚拟环境运行 `manual_eval_insufficient_context.py`。终端可用 `.venv\Scripts\python.exe -X utf8 -B -u manual_eval_insufficient_context.py` 避免中文输出编码不一致。模型读取固定资料后，应说明依据不足；不要求逐字匹配某个参考答案。

### 脚本检查

5 个离线模拟检查通过：固定资料传入下一轮请求且工具映射恢复；模型直接回答时标记未覆盖目标场景；取得固定资料后超时不计为通过；反复请求工具仍遵守 3 次调用上限；缺少第 1 段时不创建客户端。检查同时确认未初始化向量模型、未生成向量、未写入日常任务日志。这些是脚本逻辑检查，不是模型质量成绩。

固定资料原文：

> RAG是一套检索增强生成流程。系统先根据用户问题从知识库中检索相关资料，再让大模型结合资料生成答案。RAG可以减少模型仅依赖内部知识回答造成的错误。

A02-2 模型回答原文：

> 知识库中只检索到关于 RAG 基本流程的说明：RAG 会先根据用户问题从知识库检索相关资料，再让大模型结合资料生成答案，以减少仅依赖模型内部知识导致的错误。（来源：`knowledge_base.txt`，段落 1）
>
> 但知识库没有提供“检索相似度阈值应该设置为多少”的具体建议或数值范围，因此我不能依据资料给出一个确定阈值。
>
> 一般来说，RAG 的相似度阈值没有统一固定值，需要根据以下因素做实验调参：
>
> - 向量模型类型
> - 相似度算法：cosine、dot product、L2 等
> - 文档切分方式
> - 知识库内容质量
> - 业务对召回率和准确率的偏好
> - 是否配合 rerank 模型
>
> 建议做法是：在验证集上测试不同阈值，观察命中率、误召回率和最终回答质量，再确定阈值。通常不要只凭经验设置一个固定值。

人工判定：

- 目标场景已覆盖：第二次模型请求收到第 1 段，之后获得非空白回答。
- 能说明知识库没有具体阈值依据，没有编造具体数值；RAG 基本流程的引用有对应资料。
- 但随后补充相似度算法、rerank、验证集调参等建议，这些不在回传资料中，不符合“资料不足时不提供无依据的设置建议”的预设标准。因此整体不通过。
- 本判定针对回答是否受到知识库依据约束，不等同于判定所有补充建议在一般技术语境下都错误。`answered` 与内容不通过可以同时成立。

当时拟定的下一步是收紧资料不足规则。用户随后调整了产品方向，现以后文的新规则和知识库扩充为准；以上原文、测试条件及旧标准下的判定保持不变。

原有 `docs/evaluation_v1.md` 的旧版 RAG 成绩与待办保持历史记录，不由本测试替代。

## 解释范围

这是一道开发阶段受控题目，用于验证指定资料条件下的回答行为。它不是检索器测试，不是独立验证集，也不能证明总体准确率或所有场景下均能正确拒答。

## 产品规则调整：2026-09-27

用户将项目定位为帮助初学者理解 AI 知识的助手，允许在资料不足时补充模型通用知识，但必须说明依据边界。严格只根据知识库回答不再是所有问题的默认合格标准。

新规则：

- 有支持结论的资料时，优先依据资料回答，并引用对应来源。
- 资料只支持部分回答时，说明缺口。允许补充通用知识，明确标注“通用知识补充，未由当前知识库验证”，不得借用前面的引用为补充内容背书。
- 本次检索无结果时，只能说明“本次未检索到支持答案的资料”，不能据此断言整个知识库或现实世界没有答案。允许提供标注后的通用知识回答。
- 标注通用知识不代表内容已经核实。补充内容仍需检查正确性、是否解决问题及不确定性表达；不能编造来源或把项目参数当作通用标准。
- 用户明确要求只依据指定资料时，遵守该要求；资料不足就说明不足。

### 评测如何调整

| 检查项 | 人工检查内容 |
| --- | --- |
| 有用性 | 是否正面回答问题，是否给出初学者能理解的解释或步骤 |
| 正确性 | 关键事实是否可核验；通用知识补充也要检查 |
| 检索质量 | 已加入并标注的目标资料是否出现在检索结果中 |
| 来源边界 | 引用是否支持对应结论，通用补充是否与资料依据区分清楚 |
| 运行表现 | 是否正常结束，调用次数和耗时如何；继续沿用现有日志 |

`answered` 仍只表示收到非空白回答。新规则下，不再因为回答包含资料外知识就直接判失败。A02-2 可以作为重新评审的样例，但本次没有逐项核验其全部补充建议，也没有运行新策略，不能宣布新版本通过。

### 当前实施状态

Agent 代码仍在无检索结果时以 `no_results` 结束；资料外回答提示词与受控脚本中的通过标准也仍属于旧版，接入新策略时需同步调整。扩充资料见 `knowledge_expansion_v1.md`，目前为待加入原有文本知识库的草案。曾尝试的独立 JSON 资料接入及链接引用改动已撤回。

下一步先补充原有文本知识库，观察知识块，再用固定问题分别检查“是否检索到”和“是否答对”。规则切换与知识库扩充分步记录，避免把两项改动的效果混在一起。评测问题可用于开发检查，但不能把针对这些问题补资料后的成绩当作独立泛化成绩。
